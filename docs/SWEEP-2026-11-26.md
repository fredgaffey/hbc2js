**Paramless catch is a miscompile, not noise.** `var x; try { x = g(); } catch (e) { x = e; }
return x;` — hermesc allocates the catch register to `x` (`Catch rX`), the handler reads
nothing, and the read is after the handler. try-shape's `bindsExc` scanned only the handler,
so the emitter dropped the `__exc` binding and printed `catch { rX = __exc; }`: `x` became
`undefined` (DIVERGENT at v84-v99 with the default passes). Fixed in `4b64f11` (liveness after
the handler, re-derived by the checker), fixture 499, repro
`tools/sweep/repros/catch-register-live-after-handler.js`. The catches that stay paramless
are dead by construction now.

LIVE residual (open BUGS row "residual `:copy` rows whose target is read later"): e.g.
react-navigation fn#2168/2171/2174 `r3 = r2; __hbc_iterClose(r3, false)` in a `__pc`
dispatch body, fn#10148 `r2 = _e2102_1`, ignite fn#12808 `r3 = _e3987_0`. Faithful when the
bytecode leaves the source unwritten on that path too; sampled fn#2839 (`r28 = r19`) is dead
on its path. Not yet checked against the bytecode one by one.
